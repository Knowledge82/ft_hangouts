# Справочная страница: что такое XML

Это не очередной этап проекта, а справочный материал — концептуальное объяснение технологии, которую мы уже вовсю используем (layout-файлы, манифест), но ни разу не разбирали саму по себе.

## Что это такое

**XML** (eXtensible Markup Language, "расширяемый язык разметки") — это формат для представления структурированных данных в виде текста, читаемого и человеком, и машиной. Технически XML — это не язык программирования (в нём нет ни переменных, ни циклов, ни функций), а именно **язык разметки**: способ обозначить, где начинается и заканчивается тот или иной кусок данных, и как эти куски вложены друг в друга.

Базовая единица XML — **элемент** (тег), обозначенный открывающей и закрывающей скобкой:

```xml
<name>Иван</name>
```

Элементы могут быть вложены друг в друга, образуя дерево:

```xml
<contact>
    <name>Иван</name>
    <phone>+34600000000</phone>
</contact>
```

Элемент может иметь **атрибуты** — дополнительные пары ключ-значение прямо внутри открывающего тега:

```xml
<contact id="1" verified="true">
```

Элемент без содержимого можно записать в сокращённой форме — самозакрывающийся тег:

```xml
<ListView android:id="@+id/contactListView" />
```
— это то же самое, что `<ListView ...></ListView>` без содержимого между тегами, просто короче для записи, если внутри ничего нет.

## Откуда взялся и зачем понадобился

XML появился в конце 1990-х (спецификация W3C 1998 года) как упрощённая версия куда более старого и громоздкого **SGML** (Standard Generalized Markup Language, 1986) — стандарта, из которого позже вырос и HTML. Задача была конкретная: нужен был формат, который одновременно:

1. **Читается человеком** — в отличие от бинарных форматов (как, скажем, скомпилированный `.class`-файл Java), XML — это обычный текст, который можно открыть в блокноте и понять структуру.
2. **Строго проверяем машиной** — в отличие от произвольного текста, XML имеет чёткие правила синтаксиса (каждый открытый тег должен быть закрыт, вложенность не может "перехлёстываться" и т.д.), поэтому парсер может однозначно сказать, корректен документ или нет, без гадания.
3. **Не привязан к конкретной предметной области** — само название "extensible" (расширяемый) значит, что теги не заданы заранее (как в HTML, где `<p>`, `<div>`, `<img>` — фиксированный список): в XML ты сам придумываешь имена тегов под свою задачу. `<contact>`, `<phone>` — это не встроенные ключевые слова языка, а просто выбранные разработчиком названия для своих данных.

## Какие задачи он решает

Практическое применение XML сводится к одной вещи: **передача или хранение структурированных данных так, чтобы их могла прочитать программа, написанная кем угодно, на чём угодно**. Отсюда и распространённость в:

- **Конфигурационных файлах** — именно наш случай в Android: layout-файлы (`activity_main.xml`) описывают структуру экрана, `AndroidManifest.xml` — метаданные приложения.
- **Форматах документов** — `.docx`, `.xlsx`, `.pptx` (форматы Microsoft Office) — это на самом деле **ZIP-архивы, внутри которых лежат XML-файлы**, описывающие текст, стили, структуру документа. Если переименовать `.docx` в `.zip` и распаковать — увидишь папку с XML-файлами.
- **Обмене данными между системами** — раньше повсеместно использовался формат **SOAP** (протокол веб-сервисов на основе XML) для взаимодействия между разными серверами; сейчас в этой роли его во многом вытеснил JSON (см. ниже, почему).
- **RSS/Atom-лентах** — формат, которым сайты публикуют список последних статей/новостей для читалок — тоже XML.
- **SVG** — формат векторной графики, тоже XML по своей структуре (теги описывают фигуры: круги, линии, пути).

## Насколько распространён сегодня

Здесь стоит быть честной: XML **не то модное явление**, каким был лет 15-20 назад. Для передачи данных между веб-сервисами его в основном вытеснил **JSON** (JavaScript Object Notation) — более компактный, без обязательных закрывающих тегов, изначально ближе к структурам данных JavaScript, но по сути решающий ту же задачу структурированного представления данных. Если ты дальше пойдёшь в веб-разработку — 95% API, с которыми будешь работать, будут отдавать JSON, а не XML.

**Но конкретно в Android-разработке XML остаётся стандартом** для описания UI (layout-файлов) и конфигурации (манифест, strings-ресурсы для локализации, о которых мы ещё поговорим для нашего проекта) — эту роль JSON не занял, потому что у XML для этой конкретной задачи (иерархическая структура элементов интерфейса с атрибутами) синтаксис исторически лёг удобнее, и вся инфраструктура Android SDK построена вокруг XML-ресурсов. Так что для нашей текущей работы это совсем не устаревшая, а вполне живая и рабочая часть стека.

## Как читать XML — практически, на нашем примере

Возьмём файл, который мы уже писали:

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical">

    <ListView
        android:id="@+id/contactListView"
        android:layout_width="match_parent"
        android:layout_height="match_parent" />

</LinearLayout>
```

Разбор построчно:

**Строка 1** — `<?xml version="1.0" encoding="utf-8"?>` — это **XML-декларация**, обязательная первая строка любого "правильного" XML-файла. Не тег в обычном смысле (обрати внимание на `?` вместо обычных скобок) — это метаинформация о самом документе: какой версии стандарта он следует и в какой кодировке текста записан (`utf-8` — чтобы кириллица, если она попадёт в файл, отображалась корректно).

**Строка 2** — `<LinearLayout xmlns:android="..." ...>` — это **открывающий тег корневого элемента**. `LinearLayout` — имя тега, в данном случае совпадающее с именем реального Android-класса `android.widget.LinearLayout`. Это не совпадение — Android-система при чтении layout-файла буквально инстанцирует Java-объекты этого класса по именам тегов.

`xmlns:android="http://schemas.android.com/apk/res/android"` — **объявление пространства имён** (namespace). Это говорит парсеру: "все атрибуты с префиксом `android:` дальше в этом документе относятся вот к этому конкретному словарю/схеме Android". Ссылка на `schemas.android.com` не означает, что документ реально куда-то ходит по этому URL за инструкциями — это просто уникальный идентификатор-строка, соглашение, чтобы не было коллизий, если в один XML-документ попадут атрибуты из разных источников с одинаковыми именами (например, `android:id` и какой-нибудь гипотетический `custom:id` не перепутаются).

**Атрибуты** (`android:layout_width="match_parent"` и подобные) — пары ключ-значение внутри тега. У Android-виджетов практически весь набор настраиваемых свойств (размер, отступы, цвет, текст) задаётся именно через атрибуты, а не через вложенные теги.

**Символ `/` в конце тега** (`<ListView ... />`) — обозначает, что у элемента нет дочерних элементов и содержимого, тег сам себя закрывает. Эквивалент `<ListView ...></ListView>`, просто компактнее.

**Отступы (индентация)** — не обязательны синтаксически (XML не чувствителен к пробелам между тегами так же, как, скажем, Python чувствителен к отступам в коде), но это **соглашение хорошего тона**, чтобы визуально было видно вложенность: `ListView` находится на уровень глубже `LinearLayout`, значит он — дочерний элемент внутри него. Без единообразных отступов длинный XML-файл превращается в нечитаемую кашу.

**Одна и только одна пара тегов на корневом уровне.** У XML-документа обязан быть **ровно один** корневой элемент — здесь это `LinearLayout`. Нельзя на верхнем уровне файла иметь два независимых тега без общего родителя — синтаксис такого не допустит, парсер выдаст ошибку.

## Ключевое правило корректности — "well-formed" XML

В отличие от HTML (браузеры исторически прощают массу синтаксических вольностей — незакрытые теги, неправильную вложенность), **XML требует строгой корректности**. Если тег открыт — он обязан быть закрыт, причём закрытие должно происходить в правильном порядке (последний открытый — первым закрытым, как скобки в математическом выражении или как стек в программировании):

```xml
<!-- ПРАВИЛЬНО -->
<a><b></b></a>

<!-- НЕПРАВИЛЬНО — перехлёст закрытий -->
<a><b></a></b>
```

Если структура нарушена — Android Studio сразу подсветит ошибку в файле, а сборка проекта просто не пройдёт. Это, кстати, ровно то свойство ("строго проверяем машиной"), о котором шла речь в разделе про происхождение XML — синтаксическая нестрогость была бы источником трудноуловимых багов.

## Комментарии в XML

На случай, если понадобится оставить пояснение внутри файла (не для нашего текущего кода, но полезно знать):

```xml
<!-- Это комментарий, парсер его полностью игнорирует -->
```

Аналог `/* ... */` в C — не выполняется, не влияет на итоговую разметку, служит только для человека, читающего файл.
