# Этап 2. Git-репозиторий и синхронизация между кампусом и домом

## Задача

Работа над проектом ведётся с двух машин: кампусной (Linux, окружение настроено под `/goinfre`, см. [`00-nastroika-okruzheniya.md`](./00-nastroika-okruzheniya.md)) и домашнего ноутбука на Debian. Нужен способ переносить прогресс между ними без ручного копирования файлов.

**Решение:** репозиторий на GitHub (`github.com/Knowledge82/ft_hangouts`), с чётким разделением на то, что коммитится, и то, что генерируется заново на каждой машине.

## Принцип: исходники — да, сгенерированное — нет

Android Studio и Gradle в процессе работы создают большой объём вспомогательных файлов — кеши, скомпилированные классы, локальные настройки IDE, специфичные для конкретной машины. Всё это пересоздаётся автоматически при следующем открытии проекта и не должно попадать в Git — аналог того, почему в C-проектах не коммитят `.o`-файлы и бинарники после `make`, только здесь объём мусора кратно больше.

## `.gitignore`

Android Studio обычно генерирует базовый `.gitignore` сама при создании проекта. Ключевые пункты и обоснование каждого:

```gitignore
*.class
/build
/app/build

local.properties

.idea/workspace.xml
.idea/tasks.xml
.idea/shelf/
*.iml

.gradle/
.DS_Store
/captures
.externalNativeBuildBuild
.cxx/
```

**`local.properties`** — критически важно не коммитить. Здесь Android Studio записывает **путь к SDK на конкретной машине** (на кампусе — `/goinfre/vdarsuye/Android/Sdk`, дома путь будет другим). Если закоммитить этот файл, при открытии проекта на другой машине IDE попытается искать SDK по несуществующему пути и не сможет собрать проект. Файл обязан генерироваться заново на каждой машине — это штатное поведение Android Studio при первом открытии проекта.

**`/build`, `/app/build`** — результаты компиляции (то, что Gradle генерирует при сборке `.apk`). Пересоздаются с нуля при каждой сборке, хранить их в репозитории бессмысленно и тяжело.

**`.idea/`** (частично) — папка настроек именно IDE, а не проекта. `workspace.xml` (какие вкладки открыты, положение окон) — персонально для машины/сессии, игнорируется. Некоторые файлы внутри `.idea/` в принципе можно коммитить осознанно (например, единый стиль форматирования кода), но в этом проекте решено не усложнять и игнорировать папку целиком за минимальными исключениями.

**`.gradle/`** — локальный кеш Gradle, аналог того, зачем `GRADLE_USER_HOME` был вынесен в goinfre на кампусе (см. этап 0) — то же соображение применимо и к репозиторию: это кеш, не источник истины.

## Что обязательно сохраняется

- **`app/src/`** — весь код (`.java`), ресурсы (`res/`), манифест. Ядро проекта.
- **`build.gradle.kts`** (корневой и `app/build.gradle.kts`) — конфигурация сборки, версии зависимостей.
- **`settings.gradle.kts`** — список модулей проекта.
- **`gradle/wrapper/`** (`gradle-wrapper.properties`, `gradle-wrapper.jar`) — **Gradle Wrapper**. Гарантирует, что на обеих машинах используется одна и та же версия Gradle, которая скачивается автоматически при первой сборке, а не берётся из того, что случайно установлено локально. Если не закоммитить — версии Gradle между кампусом и домом могут разойтись и вызвать трудноуловимые ошибки сборки.
- **`gradlew`, `gradlew.bat`** — скрипты запуска Gradle Wrapper из командной строки (пригодится для сборки вне IDE).
- Сам **`.gitignore`**.

## Практические команды

Инициализация в корне проекта (там же, где `app/`, `gradle/`, `build.gradle.kts`):

```bash
git init
git status   # проверить, что untracked files не включают local.properties, build/, .gradle/
```

Создание репозитория на GitHub — через веб-интерфейс, без автогенерации README/gitignore/license (чтобы не создавать конфликт с уже существующим локальным проектом при первом пуше).

Подключение и первый пуш:

```bash
git remote add origin git@github.com:Knowledge82/ft_hangouts.git
git add .
git commit -m "Initial project setup: DatabaseContract, Contact model, DatabaseHelper"
git branch -M main
git push -u origin main
```

## Продолжение работы на второй машине

```bash
git clone git@github.com:Knowledge82/ft_hangouts.git
```

Открыть в Android Studio как существующий проект. IDE сама:
- сгенерирует `local.properties` с путём к SDK, актуальным именно для этой машины;
- через Gradle Wrapper скачает нужную версию Gradle, если её ещё нет локально.

Никаких ручных правок конфигурации, кроме самого клонирования, не требуется — в этом и есть смысл разделения "исходники / сгенерированное" в `.gitignore`.
