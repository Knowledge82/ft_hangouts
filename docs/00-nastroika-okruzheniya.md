# Этап 0. Настройка окружения на кампусной машине 42

## Зачем отдельный этап документации про окружение

Это не про код приложения, а про инфраструктуру — но именно она заняла значительную часть времени в начале работы, и грабли здесь типичны для любого 42-кампуса, где машины общие и жёстко ограничены по диску. Стоит зафиксировать, что и почему было сделано, чтобы при следующей настройке (на другой машине кампуса, например) не проходить это заново методом проб и ошибок.

## Исходная проблема

Кампусная машина устроена так:

- `/home/<user>` смонтирован как **отдельный, очень маленький раздел** (`/dev/sdb`, файловая система XFS, размер всего **4.7 ГБ**, без поддержки квот на уровне ФС — `noquota` в опциях монтирования).
- `/goinfre` — общий рабочий раздел, отдельный от `/home`, гораздо больше (в нашем случае 228 ГБ), с персональной подпапкой на каждого студента (`/goinfre/<user>`).

Android Studio, Android SDK, эмулятор и Gradle в сумме требуют **8–10+ ГБ** только на первую установку и синхронизацию — это физически не помещается в 4.7-гигабайтный `/home`, даже если там больше ничего нет.

## Принцип решения

Всё, что может занимать много места, должно физически лежать в `/goinfre/<user>/`, а не в `/home/<user>/`. Разные компоненты Android-тулинга используют разные механизмы для определения "куда писать", поэтому единого выключателя нет — пришлось разобраться с каждым по отдельности.

### 1. Сам Android Studio и Android SDK

Дистрибутив (`android-studio-*.tar.gz`) — это просто архив, установка не требует `sudo`, поэтому распаковывается прямо в `/goinfre/<user>/`:

```bash
cd /goinfre/vdarsuye
tar -xzf android-studio-*.tar.gz
```

При первом запуске мастер настройки (**Setup Wizard**) предлагает **Standard** или **Custom** режим установки:
- **Standard** — использует дефолтные пути (обычно куда-то в `$HOME`), без возможности их сменить на этом же экране.
- **Custom** — даёт явно указать путь к SDK.

Выбирали **Custom**, чтобы на экране "SDK Components Setup" прописать:
```
/goinfre/vdarsuye/Android/Sdk
```

### 2. Конфиги, кеш и данные самого IDE

Даже если Android Studio и SDK лежат в goinfre, **сам IDE по умолчанию пишет свои настройки, кеш и логи в домашнюю директорию** — в стандартные для Linux-приложений пути:
- `~/.config/Google/AndroidStudio*` — настройки
- `~/.cache/Google/AndroidStudio*` — кеш
- `~/.local/share/Google/AndroidStudio*` — данные

Эти пути определяются через переменные окружения стандарта **XDG Base Directory** (`XDG_CONFIG_HOME`, `XDG_CACHE_HOME`, `XDG_DATA_HOME`) — если их явно не задать, приложения, следующие этому стандарту (в том числе JetBrains IDE), используют пути по умолчанию внутри `$HOME`.

Решение — явно переопределить эти переменные в конфиге shell'а (`~/.zshrc`, так как на машине используется zsh, а не bash):

```bash
export XDG_CONFIG_HOME="/goinfre/vdarsuye/android-studio-config/config"
export XDG_CACHE_HOME="/goinfre/vdarsuye/android-studio-config/cache"
export XDG_DATA_HOME="/goinfre/vdarsuye/android-studio-config/share"
```

**Важный урок:** переменные окружения, прописанные в `.zshrc`, подхватываются только **новыми** сессиями shell'а. Если Android Studio была запущена из терминала, где `source ~/.zshrc` ещё не выполнялся после правки файла — сам процесс IDE наследует **старое** окружение и продолжает писать в старые пути, даже если переменные потом появились в файле конфигурации. GUI-процесс не перечитывает `.zshrc` "на лету". Из этого следует практическое правило: после изменения `.zshrc` — либо `source ~/.zshrc` в том же окне терминала перед запуском `studio.sh`, либо открыть новое окно терминала.

### 3. Gradle

Gradle (система сборки) по умолчанию хранит скачанные зависимости, плагины и кеш сборки в `~/.gradle` — это оказалась самая тяжёлая директория из всех (в какой-то момент разрослась до **1.4 ГБ** прямо в `/home`, потому что при одном из запусков IDE переменная окружения не была подхвачена по причине, описанной выше).

Решение — переменная `GRADLE_USER_HOME`:

```bash
export GRADLE_USER_HOME="/goinfre/vdarsuye/gradle-home"
```

Когда обнаружилось, что `~/.gradle` всё же успел вырасти до 1.4 ГБ несмотря на прописанную переменную — стало ясно, что дело именно в порядке запуска (см. пункт про XDG выше). Решено было перенести уже накопленные данные вручную, чтобы не качать заново:

```bash
mv ~/.gradle/* /goinfre/vdarsuye/gradle-home/
```

### 4. Android SDK — пользовательские данные (AVD, эмуляторы)

Отдельно от самого SDK (`ANDROID_SDK_ROOT` — где лежат платформы, инструменты сборки) существует **пользовательская** директория `~/.android`, где хранятся образы виртуальных устройств (AVD) — потенциально самые тяжёлые файлы из всех, по несколько гигабайт на каждый эмулятор. Она не покрывается XDG-переменными — это legacy-путь, специфичный именно для Android-тулинга.

Решение — переменная `ANDROID_USER_HOME`:

```bash
export ANDROID_USER_HOME="/goinfre/vdarsuye/android-studio-config/dotandroid"
```

### Итоговый набор переменных в `~/.zshrc`

```bash
export XDG_CONFIG_HOME="/goinfre/vdarsuye/android-studio-config/config"
export XDG_CACHE_HOME="/goinfre/vdarsuye/android-studio-config/cache"
export XDG_DATA_HOME="/goinfre/vdarsuye/android-studio-config/share"
export GRADLE_USER_HOME="/goinfre/vdarsuye/gradle-home"
export ANDROID_USER_HOME="/goinfre/vdarsuye/android-studio-config/dotandroid"
```

**Правило запуска:** Android Studio нужно стартовать строго из терминала, где эти переменные точно применены (проверяется через `echo $GRADLE_USER_HOME` и т.д. перед запуском `studio.sh`), иначе процесс унаследует окружение без них.

## Побочная задача: расчистка `/home`

Пока разбирались с Android Studio, обнаружилось, что `/home/vdarsuye` был забит не только связанным с Android мусором, но и накопившимся за долгое время хламом от других задач. Пришлось почистить, чтобы вообще было куда писать что-либо:

- `~/.local/share/Trash` (корзина) — 564 МБ
- Кеш Google Chrome (`~/.config/google-chrome/Default/Cache*`) — часть от 627 МБ профиля
- npm-кеш (`npm cache clean --force`) — 327 МБ
- Неиспользуемые установщики: `Insomnia.AppImage` (142 МБ), `tsetup.5.2.2.tar.xz` (Telegram, 55 МБ)
- Недокачанный файл браузера (`*.crdownload`)
- Полностью неиспользуемый Telegram Desktop и его кеш (`~/.local/share/TelegramDesktop`, 238 МБ)

Итог: с "меньше 50 МиБ свободно" до стабильных 1.5–2 ГБ на разделе `/home` — этого достаточно, чтобы система и мелкие бытовые программы работали нормально, при том что весь тяжёлый Android-тулинг живёт в `/goinfre`.

## Итоговая проверка

После настройки при запуске Android Studio строго из терминала с примененными переменными окружения:
```bash
echo $GRADLE_USER_HOME    # /goinfre/vdarsuye/gradle-home
du -sh ~/.gradle          # несколько КБ — новый Gradle-кеш больше не растёт в /home
/goinfre/vdarsuye/android-studio/bin/studio.sh
```

Предупреждение "Less than 50 MiB is left on the system directory partition" больше не появляется.

## Урок на будущее

Если придётся настраивать окружение на **другой** машине кампуса (не факт, что у неё та же схема разделов) — первым делом проверить:
```bash
df -h /home/$USER
mount | grep $USER
```
и только по факту решать, нужен ли вообще перенос в goinfre, или на конкретной машине `/home` достаточно просторный.
