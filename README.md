# ft_hangouts

Проект 42 Outer Core: Android-приложение для управления контактами с возможностью обмена SMS-сообщениями.

> Подробная, пошаговая документация каждого этапа работы — в папке [`docs/`](./docs). Этот README даёт только общую картину: что за проект, какие требования, какой стек и почему.

---

## О проекте

ft_hangouts — первый проект Outer Core, посвящённый мобильной разработке. Задача — на практике разобраться, как работает Android-приложение и как оно взаимодействует с операционной системой: жизненный цикл экранов, графический интерфейс, персистентное хранение данных, системные разрешения, интеграция с SMS-подсистемой, локализация.

Приложение позволяет:
- создавать, редактировать и удалять контакты (минимум 5 полей на контакт);
- видеть список контактов на главном экране и открывать карточку каждого;
- обмениваться SMS с сохранёнными контактами и видеть историю переписки;
- переключать язык интерфейса вместе с системным языком устройства;
- видеть, сколько времени прошло с последнего сворачивания приложения;
- менять цвет шапки через меню.

Данные хранятся в собственной SQLite-базе — использование системной таблицы контактов Android (`ContactsContract`) запрещено условием задания.

## Стек и ключевые решения

| Аспект | Решение | Почему |
|---|---|---|
| Язык приложения | **Java** | Плавный переход от C/C++ без null-safety и другого синтаксического груза Kotlin; больше документации именно под "голый" Android SDK. |
| Система сборки | **Gradle, Kotlin DSL** (`build.gradle.kts`) | Современный подход, статическая типизация конфигурации, лучше автокомплит в IDE. |
| БД | **Собственная SQLite-схема** через `SQLiteOpenHelper`, без Room | Задание запрещает внешние библиотеки; Room — часть Jetpack, к делу не подходит. |
| UI | Классические View-компоненты (`LinearLayout`, `ListView`), без Jetpack Compose | Формулировка "no external libraries including for UI design" трактуется консервативно, чтобы не спорить на защите. |
| IDE | Android Studio | Официально рекомендован заданием. |

Полное обоснование каждого решения — в [`docs/`](./docs).

## Разбор требований

### Обязательная часть

- [ ] Создание контакта (≥5 полей)
- [ ] Редактирование контакта
- [ ] Удаление контакта
- [ ] Список контактов на главном экране (summary)
- [ ] Отправка SMS контакту
- [ ] Приём SMS от сохранённых контактов
- [ ] История переписки (отправитель/получатель)
- [ ] Меню смены цвета шапки
- [ ] Поддержка двух языков + реакция на смену системного языка
- [ ] Toast с таймстемпом последнего сворачивания приложения
- [ ] Поддержка portrait и landscape
- [ ] Иконка приложения — лого 42

### Бонусная часть

- [ ] Фото профиля у контакта
- [ ] Автосоздание контакта при сообщении с неизвестного номера
- [ ] Material Design UI
- [ ] Звонок контакту прямо из приложения

### Ограничения задания

- Никаких внешних библиотек, включая UI-библиотеки.
- Никакой системной таблицы контактов — только собственная SQLite-схема.
- Оценка только людьми (peer review).

## Как продолжить работу на другой машине

```bash
git clone git@github.com:Knowledge82/ft_hangouts.git
```

Открыть в Android Studio как существующий проект — `local.properties` (путь к SDK) сгенерируется автоматически под конкретную машину, Gradle Wrapper подтянет нужную версию Gradle сам.
